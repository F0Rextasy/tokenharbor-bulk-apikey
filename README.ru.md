## ✨ Зачем это нужно

Token Harbor — это панель на Next.js (аутентификация через Supabase), бесплатный тариф которой
**основан на процентах**: личное **7-дневное окно** начинается с вашего первого бесплатного запроса
и расходует долю от прайс-листа, а не фиксированное количество запросов. Регистрация — это e-mail +
пароль с **виджетом Cloudflare Turnstile** и лимитом на сеть — одна сеть означает один аккаунт —
поэтому массовый запуск — это на самом деле «один свежий выход на аккаунт».

После регистрации стоят два барьера, и оба легко пропустить: API отвечает
`403 email_verification_required`, пока не открыта ссылка из письма о регистрации, а каждый
маршрут `:free` отвечает `403 free_models_disabled`, пока не включено согласие на бесплатные
модели — и этот эндпоинт согласия **проверяет текст, который показал клиент** (`shown_text`),
поэтому голый `{"free_models_enabled":true}` отвечает `400 reload_and_retry`. Этот CLI делает всё
это, читает id действий Next.js с живой страницы при каждом запуске и записывает только те ключи,
которые проходят живой chat-200.

## 🎁 Бесплатный тариф — сколько вы получаете

| Что | Значение |
| --- | --- |
| Бесплатные модели | **4** — DeepSeek V4.1 Flash, DeepSeek V4 Flash, MiMo V2.5, MiMo V2.6 Flash (суффикс `:free`) |
| Лимит | **процент от прайс-листа**, без фиксированного количества запросов (измерено: всё ещё `0%` после ~25 вызовов) |
| Окно | **личное, 7 дней**, начинается с вашего первого бесплатного запроса (заголовок `x-th-free-resets`) |
| Лимит на аккаунт | **60 запросов/мин**, **1 800 запросов/ч** |
| Лимит на IP | **100 запросов/мин**, **3 000 запросов/ч** (при превышении — `429` или HTTP `200` с телом `error`, и указывается время ожидания) |
| Параллелизм | не ограничен |
| Платные модели | 70+ (Claude, Grok, GLM, MiMo Pro …) — им нужны кредиты; аккаунт с нулевым балансом отвечает `402` |
| Нужна карта | **Нет** |
| Нужен телефон | **Нет** |
| Капча | **Cloudflare Turnstile** при регистрации — `src/solver.js` создаёт настоящий токен в закадровом Chrome через тот же выход |
| Подтверждение e-mail | **обязательно** — CLI открывает ссылку и следует за `307` к `?verify=success` |
| Единица масштабирования | **один аккаунт = один ключ** → `--count N` — это на самом деле «N аккаунтов из N сетей» |

Заголовки, которые стоит логировать: `x-th-plan`, `x-th-free-used-pct`, `x-th-free-resets`,
`x-th-upstream-model`, `x-th-route-decision`.

## 🧪 Как использовать API

```bash
curl https://tokenharbor.ai/v1/chat/completions \
  -H "Authorization: Bearer $TOKENHARBOR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-v4.1-flash:free","messages":[{"role":"user","content":"hi"}]}'
```

```python
from openai import OpenAI

client = OpenAI(base_url="https://tokenharbor.ai/v1", api_key="YOUR_KEY")
print(client.chat.completions.create(
    model="deepseek-v4.1-flash:free",
    messages=[{"role": "user", "content": "hi"}],
).choices[0].message.content)
```

## 🚀 Одна команда

```bash
npm start            # меню → "Mint keys" → сколько → готово
```

`npm start` открывает лаунчер, **1) Mint keys** спрашивает количество и больше ничего, затем CLI
создаёт один аккаунт на ключ, проверяет каждый живым вызовом чата и записывает выживших
в `keys.txt`.

## 🛠 Быстрый старт

```bash
git clone https://github.com/F0Rextasy/tokenharbor-bulk-apikey.git
cd tokenharbor-bulk-apikey
npm install
echo "YOUR_MAILTRAP_TOKEN" > mailtrap.txt   # ОБЯЗАТЕЛЬНО — см. предупреждение ниже
npm start            # меню → 1) Mint keys → сколько → готово
```

> **Без `mailtrap.txt` создание ключей вообще не может работать.** Token Harbor отклоняет все
> публичные домены почтовых ящиков, поэтому ничто не может прочитать ссылку подтверждения, и каждый
> аккаунт застрянет на `403 email_verification_required`. Запасного варианта нет: сначала получите
> бесплатный токен.

**Токен Mailtrap — единственный шаг настройки.** Token Harbor
принимает почтовый домен, который выглядит как настоящий хост для входящей почты, и отвечает
«complete the human check» на публичные одноразовые домены (для них он даже не отображает виджет),
поэтому CLI нужен почтовый ящик, который он может читать. Бесплатного тарифа достаточно: создайте
аккаунт на [mailtrap.io](https://mailtrap.io) → **Settings → API Tokens**, затем запишите это
значение в `mailtrap.txt` рядом с `package.json` (одна строка) или экспортируйте `MAILTRAP_TOKEN`.
Лаунчер проверяет его и сообщает, если он отсутствует — он никогда не запрашивает само значение.

Без токена CLI всё равно сначала пробует публичные почтовые сервисы, и каждый аккаунт
останавливается на стене проверки человека в панели — вот почему файл обязателен, а не опционален.

## ✅ Проверено в работе — каждый ключ тестируется

Ключ записывается в `keys.txt` только после того, как при создании:

- живой `chat-200` на модели `:free`, и
- **два разных запроса** отвечают 200 с непустым и **разным** содержимым.

Измерено от начала до конца (`node src/cli.js --auto --count 1 --pool proxies.txt`):

```
[1/1] mailbox th-…@inbound-mailtrap.io (mailtrap)
   precheck 200 · human check no
   signup 200 · session ok
   verify 307 https://tokenharbor.ai/dashboard?verify=success
   consent 200
   key 201
  ✔ thk_live_… saved to keys.txt (1/1)
done
```

Перепроверить в любой момент: `npm start` → **2) Verify keys** (`node src/cli.js --verify`);
мёртвые ключи перемещаются в `keys-dead.txt`, ключ, чей живой гейт не смог завершиться (например,
сеть попала под лимит запросов), попадает в `keys-unverified.txt`, чтобы аккаунт никогда не терялся.

## 🧭 Как это работает

1. **Почтовый ящик** — свежий инбокс на каждый аккаунт в вашем аккаунте Mailtrap (`mailtrap.txt`);
   публичные mail.tm / mail.gw — запасные сервисы.
2. **Регистрация** — id серверных действий Next.js (`next-action`, `$ACTION_KEY`,
   `x-deployment-id`) читаются с живой страницы при каждом запуске, поэтому повторный деплой панели
   не ломает CLI; отпечаток устройства и часовой пояс передаются с запросом, а часовой пояс
   измеряется по выходу, а не по вашей машине.
3. **Проверка человека** — когда панель отображает виджет, регистрация воспроизводится в настоящем
   Chrome (`src/solver.js`, `puppeteer-core` + уже установленный Chrome; `--enable-automation`
   намеренно подавляется), флажок кликается мышью, и cookies сессии этого браузера передаются
   обратно в CLI.
4. **Подтверждение e-mail** — открывается ссылка из почтового ящика; токен расходуется
   на сервере и отвечает `307 → /dashboard?verify=success`.
5. **Согласие на бесплатные модели** — `POST /api/me/privacy` с текстом согласия, который
   показывает панель (`src/consent-text.txt`), `screen: "consent_modal"`, `path: "/dashboard"`.
6. **Ключ + живой гейт** — `POST /api/keys`, затем два разных запроса должны оба ответить 200 с
   разным содержимым, прежде чем ключ будет записан.

## ⚙️ Опции CLI

```bash
node src/cli.js --auto --count 5             # пять аккаунтов → пять ключей
node src/cli.js --auto --count 5 --pool proxies.txt
node src/cli.js --verify                     # живая проверка keys.txt, мёртвые → keys-dead.txt
node src/cli.js --screen --pool proxies.txt  # какие выходы вообще достигают панели
node src/cli.js --models                     # список бесплатных моделей (нужен ключ)
node src/cli.js --help
```

| флаг | значение |
| --- | --- |
| `--count <n>` | сколько аккаунтов (и ключей) создать, по умолчанию 1 |
| `--pool <file>` | список прокси, один выход на строку (`http://host:port`, `socks5://user:pass@host:port`, `host:port`); встроенные комментарии `#` допустимы |
| `--headless` | запускать резервный браузер в headless-режиме (по умолчанию: закадровое окно, чего и ожидает капча) |
| `--screen` | проверить пул против панели и вывести live/dead для каждого выхода |
| `--verify` | живая проверка `keys.txt`; мёртвые ключи записываются в `keys-dead.txt` |
| `--models` | вывести id бесплатных моделей |
| `--strict-proxy` | никогда не отправлять прямой запрос: живой гейт тоже должен идти через пул (переменная окружения `TOKENHARBOR_STRICT=1` делает то же самое) |

Умирающий выход никогда не стоит аккаунта: регистрация и живой гейт оба повторяются на других
строках пула, а лимит запросов (`429` или `200`, в теле которого есть `rate_limit_exceeded`)
ожидает время, указанное панелью.

## 🛰️ За прокси

По умолчанию CLI работает **напрямую**. Поместите один выход на строку в `proxies.txt` (лаунчер
подхватывает его автоматически) или передайте `--pool`:

```text
http://127.0.0.1:8080
socks5://user:pass@10.0.0.5:1080
10.0.0.5:8080
```

Опционально — рекомендуется при масштабе: панель ограничивает регистрации **на сеть**, поэтому один
свежий выход на аккаунт поддерживает здоровье более крупного запуска. Почта читается напрямую из
вашего аккаунта Mailtrap (почтовый провайдер — это не панель), поэтому медленный выход не может
сломать шаг с почтовым ящиком.

## 🔌 Подключение к 9Router

```bash
node src/connect-9router.js --base http://localhost:20128 --password 123456
```

Регистрирует один узел провайдера `openai-compatible` (`tokenharbor`, базовый URL
`https://tokenharbor.ai/v1`) и одно соединение на каждый ключ в `keys.txt`, так что 9Router
балансирует нагрузку между вашими ключами. Идемпотентно: существующий узел или соединение
переиспользуется, а нумерация продолжается с наибольшего уже имеющегося `tokenharbor-0NN`.

## 🔌 Подключение к OmniRoute

```bash
node src/connect-omniroute.js --base http://localhost:20128 --password 123456
```

Та же схема для OmniRoute (узел провайдера + одно соединение на каждый ключ). Лаунчер предлагает
оба варианта как пункты меню **6** и **7**, а `npm run 9router` / `npm run omniroute` делают то же
самое.

## 🔑 Что даёт один ключ

- четыре модели `:free` выше, при 60 запросах/мин и 1 800 запросах/ч на аккаунт (100 запросов/мин на IP);
- лимит на основе процентов внутри личного 7-дневного окна (`x-th-free-resets` сообщает, когда
  он сбрасывается);
- OpenAI-совместимый `/v1/chat/completions` с вызовом функций, поэтому любой OpenAI SDK, CLI или
  роутер работает, если изменить `base_url` на `https://tokenharbor.ai/v1`;
- платные модели остаются заблокированными, пока на аккаунте нет кредитов (иначе `402`).

## 🐞 Проблемы

Откройте issue с командой, шагом, на котором произошёл сбой (CLI выводит `precheck / signup /
verify / consent / key / chat`), и сообщением самой панели. Никогда не вставляйте полный API-ключ —
достаточно последних четырёх символов.
